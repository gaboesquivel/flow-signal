Triage

Clear the queue one row at a time. Each suggestion is a line of pencil until you accept, edit, or reject it; the open row holds everything needed to decide, read side by side.

Steps
  1. Queue: seven pending suggestions, the merge open.
  2. Accept the merge: Dana's signal moves; Undo merge stays on the row for the session.
  3. Open the need: the merge sits in its history with Undo merge.
  4. Edit a draft need's statement, then approve it.
  5. Accept a split: four signals move to a new need.
  6. Approve a public summary, with the PII check line.
  7. Reject a theme, with an optional reason.
  8. Accept the last two drafts: All caught up.
Try it
Everything in the light desktop frame works. Click a row to open it. j/k move, a accept, e edit, r reject, esc cancel, ⌘↵ saves an edit. The step strip replays the flow to each state. Dark and phone frames show step 1 and are static.
API
list_suggestions (pending, newest first) feeds the queue. Accept, edit, and reject call resolve_suggestion with the edits each kind allows: merge {intoNeedId}, draft need {statement}, split {statement, signalIds}, summary {summary}, theme {themeId} or {themeName}. Undo calls undo_merge with the mergeId the accept returned. The need view reads get_need_detail (its merges list); 4b designs the full need page.
Not in API
not in APIReject reason: resolve_suggestion takes no reason, so it is shown but would be dropped. not in APIPII check line: computed in the client here by matching submitter names, account names, and emails. The server doesn't return it. The confidence label from round 2 is gone because suggestions carry only a reason.
Risks
Dana's draft would also have its own pending draft need suggestion. Accepting the merge would make that one conflict, so the prototype leaves it out. After Undo merge the draft is back but nothing re-queues it. The queue is newest first, so a two-month-old summary sits at the bottom. Rejecting a draft need leaves the need a draft forever. Keyboard accept makes it easy to accept without reading.
