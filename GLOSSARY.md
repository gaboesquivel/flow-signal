# Signal — glossary

| Term                    | Meaning                                                                                                                                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Portless host**       | Local dev URL host (`signal.localhost`) used by the template's Portless configuration                                                                                                                                                 |
| **Public MCP**          | Unauthenticated MCP tools at `/api/mcp`: the template's (health, catalog, compose_ui) plus Signal's public operations                                                                                                                 |
| **Operator**            | Protected console (`/operator`) and MCP (`/api/mcp/operator`); requires `OPERATOR_SECRET`; fails closed when unset                                                                                                                    |
| **Signal**              | One person's submission, kept verbatim (their words, email, account, urgency, date); always attached to a need                                                                                                                        |
| **Need**                | The underlying problem ("who needs to do what so that outcome"); AI-drafted, PM-edited; what people support and PMs decide on                                                                                                         |
| **Draft need**          | A need created by a new signal; public as "new" until a PM approves it or merges it                                                                                                                                                   |
| **Theme**               | PM-defined area grouping related needs (e.g. "Reporting")                                                                                                                                                                             |
| **Proposed solution**   | A solution extracted by AI from signals and listed on a need; matching is on the need, not the solution                                                                                                                               |
| **Merge**               | Moving all of one need's signals onto another need; undoable, nothing is lost                                                                                                                                                         |
| **Decision**            | A PM-published outcome on a need (planned, in progress, shipped, declined) with a note supporters see                                                                                                                                 |
| **Close-the-loop rate** | Signals whose submitter saw a published decision on their My signals link ÷ signals filed on the need before that decision; one count per signal and decision                                                                         |
| **Prevention rate**     | Signals attached to an existing need at submission ÷ (those + signals whose draft need was later merged)                                                                                                                              |
| **Match exposure**      | Which needs a preview showed a submitter (`preview.shown`) and which one they chose, stamped on the signal as `exposure` ([spec 012](./docs/specs/012-match-exposure.md))                                                             |
| **Match take-up**       | Submissions shown at least one match that picked a shown need ÷ all submissions shown a match; the direct measure of riskiest assumption 1                                                                                            |
| **Merge check**         | One ask of the merge judge whether a draft need duplicates its nearest needs (up to two proposals), recorded in `merge_checks` so it re-runs only when something changed ([spec 009](./docs/specs/009-duplicate-backstop.md))         |
| **Duplicate sweep**     | Re-running due merge checks over live drafts from the last 30 days: after every submission, after `pnpm db:embed`, and on demand (`sweep_duplicates`)                                                                                 |
| **Suggested match**     | A pending merge proposal shown to the submitter on My signals ("Is this the same need?"); they join it or decline it (`answer_suggested_match`)                                                                                       |
| **Skip rate**           | Submissions sent without a `previewId` ÷ all submissions; how much the duplicate backstop carries                                                                                                                                     |
| **Report**              | A PM report: a typed spec of headings, text, KPIs, charts, and tables whose figures come only from report datasets; saved reports re-run on fresh data ([spec 013](./docs/specs/013-pm-reports.md))                                   |
| **Report dataset**      | One of a fixed catalog of read-only queries (`needs`, `signals_weekly`, `accounts`, `decisions`, `metrics_weekly`) a report can draw on; no submitter identity or verbatim text                                                       |
| **Shared report link**  | A read-only, unguessable `/r/<token>` link to a snapshot of a saved report; refreshed or revoked by the PM                                                                                                                            |
| **Operator assistant**  | Experimental console Chat (`OPERATOR_ASSISTANT=on`) that answers from read tools, shows data inline as report views, and proposes changes the PM confirms on a card ([spec 014](./docs/specs/014-operator-assistant.md))              |
| **Action proposal**     | A write the assistant proposed: held on the server with its preview until the PM confirms (optionally edited) or dismisses it; expires after 30 minutes ([0011](./docs/decisions/0011-assistant-writes-are-server-held-proposals.md)) |
| **Operation**           | One capability defined once in the registry (`lib/signal/operations/`) and exposed as a REST route, MCP tool, and agent tool                                                                                                          |
| **Parity suite**        | Tests that run each operation's cases through REST, MCP, and agent surfaces and expect the same output, errors, and events                                                                                                            |
| **My signals link**     | A submitter's private, unguessable link (`/my/<token>`) to every signal filed under it; carries forward to their next submissions, never grouped by email ([0005](./docs/decisions/0005-my-signals-link-carries-forward.md))          |
| **Pencil / ink**        | How the UI marks AI output still awaiting a person (pencil) versus text a person confirmed (ink) ([DESIGN.md](./DESIGN.md))                                                                                                           |
